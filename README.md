# Поиск объявлений услуг по запросу

Решение тестового задания по кандидатогенерации для поиска Авито. Для каждого запроса нужно выбрать до 50 объявлений из корпуса так, чтобы среди них оказалось как можно больше объявлений, выбранных пользователями. Основная метрика - Recall@50.

Давайте попробуем объединить несколько способов текстового поиска, дополнить их географией и информацией из обучающей выборки, а затем выбрать 50 кандидатов с помощью CatBoost'а (потому что бустинги это круто + перформят хорошо практически на всех типах данны). 
В результате получили Recall@50 на локальной контрольной выборке - **0,920**. Результат на скрытом бенчмарке пока неизвестен.

## Данные

Используются три файла из задания:

| Файл | Содержание |
|---|---|
| `train.parquet` | 497 673 положительные пары "запрос - выбранное объявление» |
| `benchmark_items.parquet` | Корпус из 189 212 объявлений |
| `benchmark_queries.parquet` | 2 452 запроса для итоговой выдачи |

В обучении есть только положительные пары. Поэтому отсутствие пары в `train` ещё не означает, что объявление не подходит запросу. Это учитывается при интерпретации качества модели.

##  Само решение

### 1. Подготовка текста

Все тексты мы приводим к нижнему регистру, `ё` заменяется на `е`, убираются пунктуация и лишние символы. Для словесного поиска используется русский Snowball-стеммер из NLTK (https://www.nltk.org/api/nltk.stem.SnowballStemmer.html), он сократит слова до основ, чтобы разные словоформы чаще совпадали.

Заголовок, описание и параметры объявления обрабатываются отдельно. Ограничим описания первыми 7 000 символами, чтобы уменьшить затраты памяти и время построения индекса.

### 2. Текстовый поиск

Для заголовков, описаний и параметров строятся отдельные индексы BM25. Этот метод подходит как основа решения: он учитывает совпадения слов, их редкость и длину документа.

Дополнительно используется TF-IDF по символьным n-граммам длины 3–5 в заголовках. Такой поиск помогает находить похожие написания и часть запросов с опечатками, которые могут пропустить точные совпадения слов.

### 3. Информация из train

Для нового запроса находятся 35 похожих текстов из обучающей истории. По выбранным для них объявлениям рассчитываются:

- веса микрокатегорий;
- дополнительные слова для расширения запроса из заголовков объявлений;
- частоты связей похожих запросов с конкретными объявлениями.

Также учитывается, сколько раз объявление встречалось в разрешённой обучающей истории.

География используется как дополнительный сигнал: совпадение локации, приблизительное расстояние и частота выбора объявлений из другой локации. Жёсткого ограничения одним городом нет, поскольку подходящее объявление может находиться за его пределами.

### 4. Объединение кандидатов

Из разных вариантов поиска берутся отдельные списки: по тексту, по частям слов, по расширенному запросу и по истории. После объединения и удаления повторов остаётся не более 740 кандидатов.

Такой подход нужен для полноты: если один способ поиска пропустил объявление, его может найти другой. Веса формул и размеры списков заданы вручную.

### 5. Отбор 50 объявлений

Для каждой пары "запрос - кандидат" рассчитываются 27 числовых признаков. В них входят текстовые сходства, география, микрокатегория, соответствие тексту фильтров, цена, рейтинг и число отзывов.

CatBoostClassifier обучается по этим признакам и оценивает кандидатов. В итоговый ответ попадают 50 объявлений с наибольшими оценками. Сырой текст в CatBoost не передаётся.

## Как проверялось качество

Для локальной проверки используются положительные пары из `train`, чьи объявления есть в корпусе бенчмарка. Из них выбираются 4 000 разных нормализованных текстов запросов, с большим весом редких запросов. Для каждого текста выбирается один контекст: локация, фильтры, категория и флаг доставки.

Все пары с выбранными текстами удаляются из истории, на которой строятся поведенческие признаки. Дополнительно для 90% уникальных положительных объявлений этих запросов удаляется вся история их выбора. Это приближает проверку к случаю, когда нужно находить новые объявления. Сами объявления и их тексты остаются в поисковом корпусе.

Запросы распределяются на три части:

| Часть | Запросов | Назначение |
|---|---:|---|
| `fit` | 2 400 | Обучение CatBoost |
| `dev` | 800 | Ранняя остановка по Logloss |
| `test` | 800 | Контрольная оценка Recall@50 |

Seed разбиения и обучения - `20260927`. Разбиение сделано по текстам запросов: одно объявление может встречаться у разных запросов в нескольких частях.

Найденные кандидаты без положительной метки используются как отрицательные примеры. Если генератор не нашёл известное положительное объявление, оно не добавляется в кандидаты искусственно и учитывается как пропуск при расчёте метрики.

После проверки CatBoost переобучается на кандидатных парах всех 4 000 запросов с выбранным числом деревьев. Для итогового предсказания статистика истории перестраивается по полному `train`. Значения в таблице ниже получены **до этого финального переобучения**.

## Результаты

Сравниваются три способа выбора 50 объявлений из одного объединённого набора кандидатов:

| Способ отбора | Recall@50 на dev | Recall@50 на test |
|---|---:|---:|
| Текстовая формула с географией | 0,8156 | 0,8388 |
| Гибридная формула с историей | 0,8588 | 0,8719 |
| CatBoost | **0,9000** | **0,9200** |

Полнота расширенного набора на контрольной части до сокращения до 50 составляет 0,9706. По ранней остановке выбрано 496 деревьев. Подробные метрики и важности признаков находятся в `metrics.json`.

Это локальная оценка. Разбиение не полностью повторяет распределение бенчмарка, поэтому результат скрытой проверки может отличаться.

## Как запустить

Решение проверялось на Python 3.12 и CPU. GPU не требуется. Для полного расчёта желательно около 8 ГБ свободной оперативной памяти; удобнее использовать среду с 16 ГБ RAM. После установки зависимостей обучение и предсказание работают без внешних API.

Распакуйте архив решения и положите исходные файлы в папку `upload` рядом со скриптами:

```text
upload/train.parquet
upload/benchmark_items.parquet
upload/benchmark_queries.parquet
```

Из папки решения выполните:

```bash
python -m pip install -r requirements.txt

# Подготовка индексов, разбиения и признаков
python retrieval.py --mode prepare --data upload --work work

# Обучение и расчёт локальных метрик
python retrieval.py --mode fit --work work

# Предсказания для бенчмарка
python retrieval.py --mode predict --data upload --work work --output answer.csv

# Проверка формата результата
python validate_answer.py --data upload --answer answer.csv
```

Промежуточные файлы сохраняются в `work`. Этап `prepare` выполняет полную подготовку и может занять заметное время.

В архиве также есть готовая `model.cbm`. Чтобы использовать её, выполните `prepare`, скопируйте модель в `work/model.cbm` и запустите `predict`, пропустив `fit`. Один файл модели не заменяет поисковый индекс, поэтому подготовка всё равно нужна.

## Файлы решения

| Файл | Назначение |
|---|---|
| `retrieval.py` | Обработка данных, поиск кандидатов, обучение и предсказание |
| `validate_answer.py` | Проверка итогового CSV |
| `requirements.txt` | Версии зависимостей |
| `model.cbm` | Готовая финальная модель CatBoost |
| `metrics.json` | Результаты локальной проверки |
| `input_checksums.json` | Контрольные суммы исходных данных |
| `output_validation.json` | Проверка ранее сформированного `answer.csv` |

Исходные Parquet в архив не включены. Итоговый `answer.csv` передаётся отдельно и может быть заново получен командой `predict`. В нём 2 452 строки, по 50 уникальных `item_id` в каждой. Проверяются покрытие запросов, формат идентификаторов, отсутствие повторов и наличие всех объявлений в корпусе.

## Использованные библиотеки

- pandas и PyArrow - чтение Parquet и работа с таблицами;
- NumPy и SciPy - числовые расчёты и разреженные матрицы;
- scikit-learn - словесные и символьные векторизаторы;
- NLTK - русский Snowball-стеммер;
- CatBoost - обучение модели отбора кандидатов.

В основе поиска используются стандартные методы BM25 и TF-IDF. Предобученные нейросетевые модели и внешние данные в этой версии не используются.

## Ограничения и что можно улучшить

Главное ограничение разметки - отсутствие явных отрицательных примеров. Часть кандидатов с меткой 0 тоже может подходить запросу. Кроме того, географические расстояния приблизительные, а текстовые фильтры не превращаются в строгие условия вроде минимального рейтинга.

Следующий шаг - проверить семантический поиск по векторам текстов, подобрать веса и размеры списков на `dev` и сравнить отбор с моделью ранжирования. Отдельно можно оптимизировать скорость и память: текущая реализация рассчитана на офлайн-подготовку ответа для задания.
