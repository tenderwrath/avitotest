# Поиск объявлений услуг, версия 3

Вторая версия решения получила **0,870906 Recall@50 на Stepik**. До этого
локальная оценка была заметно выше, поэтому я продолжил искать источник
расхождения, а не считал её надёжным прогнозом скрытого результата.

У предыдущей версии семантический поиск E5 использовал только заголовок
объявления. В новой версии я отдельно кодирую заголовок вместе с началом
описания. Это помогает, когда в коротком заголовке нет слов, которыми
пользователь описал услугу. Каждый запрос получает дополнительные
семантические кандидаты, а CatBoost выбирает из общего списка до 50
объявлений. Сохранились BM25, символьный TF-IDF, история похожих запросов,
география и признаки полноты совпадения текста. В итоговой выдаче для
текстов, уже встречавшихся в `train`, оставлена модель версии 2; для
новых текстов используется расширенный поиск по описанию.

При локальной проверке выяснилось, что примерно 63% текстов
`benchmark_queries` вообще не встречаются в `train`. Такие запросы в
бенчмарке обычно длиннее отложенных запросов из первой проверки и реже
используют фильтры. Поэтому обучающие примеры взвешиваются по трём
**неразмеченным признакам** бенчмарка: наличие текста в `train`, число слов
и наличие фильтра. На ответы или конкретные `query_id` эти веса не смотрят.

## Проверка

Использую 8 000 отложенных ситуаций из `train`, сформированных предыдущей
версией: `fit` для обучения, `dev` для выбора числа деревьев и `test` для
контрольного сравнения. История выбранных объявлений для этих ситуаций
скрывается при построении индекса. Положительные объявления, не найденные
генератором, не добавляются вручную и учитываются как пропуски Recall@50.

| Вариант | Полнота списка кандидатов на test | Recall@50 на test |
|---|---:|---:|
| Версия 2 на тех же запросах | 0,9696 | 0,9341 |
| Версия 3 с описаниями для всех запросов | **0,9769** | **0,9356** |
| Гибрид: версия 2 для знакомого текста, версия 3 для нового | — | **0,9379** |

При применении версии 3 ко всем запросам прирост Recall@50 на контроле
небольшой: +0,0015, и доверительный интервал разницы включает ноль.
Гибрид прибавляет +0,0038 на том же наборе. Для
запросов без истории на test прирост составил +0,0062. После выбора
гибридного правила локальный test уже не является независимой проверкой;
новое значение Stepik по этому файлу заранее неизвестно.

## Запуск готовой модели

Понадобятся Python 3.12, CPU с достаточным временем работы и около 10 ГБ
оперативной памяти. Разместите три файла `train.parquet`,
`benchmark_queries.parquet`, `benchmark_items.parquet` в папке `upload`.
В архиве проекта папка `work_v3/e5_model` содержит локальные веса открытой
модели [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small).
Запросы кодируются с префиксом `query: `, объявления — с `passage: `.
Открытых API во время работы нет.

```bash
python -m pip install torch==2.14.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r v3/requirements.txt
python v3/run.py --data upload --work work_v3 --output answer.csv
```

`run.py` кодирует корпус и запросы, строит поисковый индекс и записывает
файл. В `work_v3/classifier_v2.cbm` сохранена модель для знакомых текстов;
`classifier.cbm` используется для новых. Кодирование описаний на CPU занимает заметное время: это отдельный
индекс для 189 212 объявлений. Готовый CSV можно проверить:

```bash
python v3/validate_answer.py --data upload --answer answer.csv
```

## Как повторить обучение

Код `v2/` входит в архив как первый этап. Из корня проекта сначала
запустите предыдущий эксперимент, чтобы получить его отложенные запросы,
индекс и обученную базовую модель:

```bash
python v2/run.py --mode full --data upload --work work_v2 --output answer_v2.csv
```

Ему нужны те же веса E5 в `work_v2/e5_model`. Их можно скопировать из
`work_v3/e5_model` либо один раз скачать указанной в `v2/README.md`
командой. Далее:

```bash
python v3/dense.py --mode descriptions --data upload --work work_v3 --model-path work_v3/e5_model
python v3/features_v3.py
python v3/train_v3.py
python v3/refit_v3.py
python v3/predict_v3.py --data upload --work work_v3 --dense-work work_v2 --index-work work_v2 --output answer.csv
```

После полного обучения версии 2 скопируйте `work_v2/classifier.cbm` в
`work_v3/classifier_v2.cbm`, чтобы включить гибридное правило.

`features_v3.py` формирует кандидатов без добавления известных ответов,
`train_v3.py` считает Recall@50 обеих версий на одних запросах и выбирает
число деревьев на `dev`. `refit_v3.py` отдельно обучает финальный CatBoost. Результаты
сохраняются в `work_v3/metrics_v3.json`. Используются NumPy, pandas,
SciPy, scikit-learn, NLTK, PyArrow, PyTorch, Transformers, SentencePiece,
CatBoost и указанная открытая модель E5. Точные версии библиотек — в
`requirements.txt` и команде установки PyTorch.
